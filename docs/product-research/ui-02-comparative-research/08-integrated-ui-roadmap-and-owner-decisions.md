## 1. Strategic Comparison: Three Migration Approaches

Before mapping work into `WP01`–`WP08`, we compared three classic UI migration strategies against PCC's constraints (active `WP01` functional foundation, high feature velocity in `WP02`–`WP06`, and deferred final visual polish in `WP07`):

| Strategy | What It Does | Strengths | Fatal Weakness for PCC | Verdict |
| :--- | :--- | :--- | :--- | :--- |
| **A. Pure Repair-First (Patch Current UI Until `WP07`)** | Keep existing 3-column Inspector/Studio layout and legacy tokens until `WP06` finishes; dump all new features into existing panels; rewrite everything in `WP07`. | Zero early layout refactoring. | **Severe rework & unusable intermediate product:** Stuffing `Creative Studio`, `Story Development`, `Dual Timeline`, `Knowledge Matrix`, and `R2 Backup` into the current `398px` Inspector rail makes `WP03`–`WP06` untestable and forces throwing away 60%+ of UI glue in `WP07`. | **REJECT** |
| **B. Immediate Full Aesthetic Overhaul (Redesign First)** | Freeze `WP01`–`WP02` to pick fonts, colors, dark mode, and redesign every screen before backend contracts (`E0`–`E3`) exist. | Early visual polish. | **Directly violates Owner Direction (`§E`):** Pauses active `WP01` functional foundation, builds pretty shells over broken/missing contracts (timeline heuristics, stale anchors, embedding engines), and guarantees rewrites when real data shapes land. | **REJECT** |
| **C. Phased Skeleton + Swappable Tokens (`WP01–06`) → Full Aesthetic Overhaul (`WP07`) → Acceptance (`WP08`)** | Let `WP01`–`WP02` build functional foundations + targeted high-severity safety/usability repairs; introduce **structural IA homes + swappable semantic CSS tokens** alongside new capabilities in `WP03`–`WP06`; execute approved **Complete UI/UX Overhaul** cleanly over those tokens in **`WP07`**; verify end-to-end in **`WP08`**. | **Zero wasted rework:** Every capability lands in its permanent logical home (`Write`, `World`, `Studio`, `Develop`, `Review`, `Projects`, `Settings`) using semantic tokens, so `WP07` upgrades visual polish, typography, dark mode, and responsiveness without tearing apart state or routing! | Requires disciplined separation between *structural contracts* (`WP03–06`) and *final aesthetic styling* (`WP07`). | **RECOMMENDED (Aligns 100% with Owner `§E`)** |
