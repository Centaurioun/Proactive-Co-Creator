## 3. Six-Cycle Iterative Refinement
Use relevant Superpowers methods if installed (brainstorming, receiving/critical review, systematic debugging, planning, verification before completion); otherwise apply equivalent principles and disclose availability. Research only. Apply six substantive cycles:
1. Reconstruct independent report, earlier owner observations, latest approved decisions and actual product. Map each item, capability, evidence level and underlying intent.
2. Compare and investigate. Verify significant disputed factual claims using exact source or safe preview; compare observations, known defect vs hypothesis, actual vs projected workflows, coverage gaps and prior commitments.
3. Diverge. Generate alternative whole-product experiences, navigation and visual concepts, new combinations and new affordances beyond both streams. Preserve real alternatives before converging.
4. Challenge. Stress tasks, cognitive load, accessibility, localization, privacy, persistent state, destructive/costly actions, long narratives, responsive behavior, maintainability, rework and evidence. Critique your own earlier recommendations and new preferred concept; reject weak ideas with reasons.
5. Refine. Deliver concrete interaction specifications, coherent screen families, state transitions, visual semantics, corrected token candidates, examples, design comparison and acceptance criteria. Address owner-approved changes and counterexamples.
6. Integrate and verify. Produce traceable candidate design blueprint, recommendation portfolio and staged roadmap through WP08, decision agenda and actual refinement log. Verify coverage, links, evidence labels and documentation-only boundary.

Record actual changes of mind and rejected alternatives rather than six generic headings. Do not start implementation or repeatedly request routine owner clarification. Record open choices for final review.
