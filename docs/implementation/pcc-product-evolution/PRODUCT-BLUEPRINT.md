## 2. Product experience
PCC is a local-first, visual, narrative-aware creative partner, not a chat wrapper. Four primary jobs: seed-to-story, faithful existing narrative understanding, creative discovery, sustained development/revision. Keep four distinct data authorities: immutable source bytes/extraction provenance, editable Working Manuscript, accepted narrative model/Story Bible, immutable generated artifacts with explicit adoption. Drafts, hypotheses, unreviewed AI output and character belief never silently become canonical facts. Preserve identity, lineage, exact revision, source anchors, recoverable author decisions, privacy and explicit provider actions. Browser/preview and future native build must not require cloud embeddings or any particular computer.

Write: calm editor, outline, optional contextual margin with locally derived relevant cast/relationships, source-linked observations, approved pending suggestions and one-click handoffs. No unsolicited paid AI. World: spacious interactive Story Map, true dual-track narrative order vs chronology, uncertain event placement, relationship/ego/kinship and epistemic lenses, Story Bible. Creative Studio: Discover with AI, Guided Exploration, Focused Development, Story Lab, all accessible in Calm; collaborative exploration across modes. Story Development: Expand & Continue, Character Depth, Scene & Dialogue (voice and subtext), Pacing & Structure, Voice & Tighten (compression); preserve chosen core story and voice. Review: actual consistency issues, scope-aware diagnostics, bidirectional sync, proposed changes, history. Projects: Project Overview, activity, meaningful resume, backup/recovery, alternative lineage and compare. Story Q&A: author asks, sourced answers with scope/uncertainty and contextual bridge to Studio/Develop. No generic opaque scores or artificial completion percentages. Mobile/accessibility and keyboard/focus support. Do not merely change labels: real interactions and navigable full-sized surfaces.

## 3. Shared enablers and concrete proposal lifecycle
E0 provider/trust and durable persistence. E1 local Narrative Memory Index and optional semantic retrieval. E2 persistent CreativeSession. E3 unified proposal, validation, apply/revert and deterministic visual projection. These are separate concerns sharing existing authorities, not multiple canonical stores.

CreativeSession stores scope (seed, full story, scenes, passage, stable entities/relations/events and combinations), base identity/revision, user text, selected and unselected directions, questions/answers, rejected/retained alternatives, idea versions/parent links, notes, locks/preferences, staged concrete changes, provenance and durable save state. Persist incrementally; session edits do not mutate canonical story; autosave vs bookmark vs select vs apply remain distinct. Recover after reload, switch, failed provider or interrupted call. Never auto-resume a consumed inference on reopen. Save for Later, Dismiss (recoverable history), compare/combine, per-card Regenerate (preserve prior version and other cards), Edit idea vs Edit actual patch, Develop Further preserving essence, Suggest More Directions append distinct directions preserving selections, custom input with two independent actions Suggest Directions (directions only) and Generate Idea (concrete idea), Develop with Selected Directions, Surprise Me, Explain Differently, Challenge This Idea. Multi-select to save, dismiss, combine or stage; no direct batch mutation before reviewed concrete patch.

UnifiedProposal stores stable ID, target and base identity/revision/digests, typed operations, dependencies, source evidence and author-reviewed payload. Single or aggregate Preview displays Summary, exact Before/After, Change Map, Impact Analysis; Edit/selection regenerates the same deterministic candidate and invalidates prior approval. Distinguish actual patch from hypothetical downstream impacts. Visual projector uses exact validated before and after states and stable layout, labeled added/removed/changed/unchanged, click to matching op and source; accessible alternate view. Never let a second AI call invent the diff. Apply only explicitly selected coherent changes, enforce locks, CAS/idempotency, stale results, missing dependencies, conflicts, and durable transaction/recovery guarantees. Do not report success before persistence. Undo and safe selective revert using inverse operations and conflict-aware preview without overwriting later edits. No redundant Accept -> Send to Change Review -> Apply ceremony. Ideas accepted for consideration are not applied changes.

Final outcomes: Apply Current / Selected, Save as Alternative Project, Save Draft, Continue Exploring. Alternative is independent copy at exact reviewed base with validated patches, new identity, remapped references, separate history and provenance; original unchanged. No automatic switching: after success Continue Current Project default, Open Alternative explicit. Later optional Story Multiverse lineage, qualitative comparison and selective transfer with dependency/lock/conflict checks (not implicit Git merge). Distinguish idea alternatives, temporary sandbox, durable independent projects.

## 6. NEW — Hybrid local narrative memory and optional embeddings
Owner requests normal persistent local indexing plus optional Local Qwen, Gemini Embedding 2, Cloudflare Workers AI embeddings, separately or together. This expands E1, not a separate product or mandatory vector database.

### 6.1 Baseline mandatory offline index
Persist derived structured metadata and lexical/full-text postings locally (IndexedDB or existing authoritative storage integration with derived stores). Include stable project/source/section/scene/chunk IDs, source/extraction and manuscript distinctions, revision ID/digest, offsets, names/aliases, exact quotations, relationships, chronology and explicit epistemic/time references, thread IDs; only supported facts are indexed as accepted. Preserve author-authored summaries, notes and accepted AI artifacts in authoritative records; index references rather than owning them. Deterministic metadata and lexical retrieval rebuild without AI. Search normalizes Unicode/case with multilingual handling; support Turkish suffixes and exact phrases without deleting source offsets; benchmark rather than promise perfect linguistic retrieval. Embeddings disabled or unavailable must never break ordinary search or other project features.

### 6.2 Providers are separate optional capabilities
- Local: existing user's Qwen3-Embedding-0.6B via explicitly configured local compatible runtime/embedding API. Do not assume Ollama, LM Studio, MLX, a port or exact model alias; allow configuration and explicit synthetic connection test. Candidate model card: https://huggingface.co/Qwen/Qwen3-Embedding-0.6B (up to 1024 dimensions). Prefer loopback/native trusted bridge when actually available. Hosted GAIS server is not the owner's computer; no public tunnel, LAN exposure, credential forwarding or arbitrary URL proxy. If unavailable, skip with status; other users need not have the owner's service. Access to an explicitly configured remote private endpoint is a separate security decision, not a default.
- Gemini: Gemini Embedding 2 via official embedding endpoint and exact supported model ID/capabilities discovered in selected account; verify documentation https://ai.google.dev/gemini-api/docs/embeddings and https://ai.google.dev/gemini-api/docs/pricing. Managed generation availability does not imply embedding entitlement. Separate purpose and consent; if unavailable, show reason. No auto-provision personal key.
- Cloudflare: Workers AI REST embedding endpoint using user's separately configured scoped credentials held server-side, or future authorized Worker binding. Read-only account catalog verified 2026-11-28 includes @cf/qwen/qwen3-embedding-0.6b and @cf/baai/bge-m3; also other embeddings. Docs https://developers.cloudflare.com/workers-ai/models/qwen3-embedding-0.6b/ and https://developers.cloudflare.com/workers-ai/platform/pricing/ list 10,000 free Neurons/day (not requests), pooled with other Workers AI usage; paid excess possible, don't hardcode quota or estimate remaining usage without account evidence. No embedding inference, billing change, Cloudflare resource creation or remote index upload occurred during design. ChatGPT connector access is NOT a PCC runtime credential. User may configure integration later.
- Separate embedding from generation provider preferences, model discovery, capability and budgets. Settings supports Off (default), one, or several enabled embeddings, preferred source and explicit multi-source mode. Each has independent status, model, connection test, dimensions, usage/budget and index build/refresh controls. No silent switch to paid/external inference. If multiple already-consented sources explicitly selected for a query, unavailable sources may be skipped and visible result coverage updated. Local-only intent never sends manuscript or query to cloud.

### 6.3 Persistence, hybrid retrieval and privacy
Chunks are source-linked, bounded, stable semantic units (scene/paragraph windows with overlap as needed), offsets/digests exact. Store each vector namespace keyed by project + source/section/chunk digest + embedding provider/model/revision + dimensions + normalization/instruction/chunking version. Validate dimensions, finite values, count and association; reject stale/mixed namespaces. Even same model name across local and Cloudflare is not proven identical vector space; do not compare raw vectors/scores across incompatible providers or assume cached cloud vectors can be queried locally. Keep prior namespaces until user chooses cleanup; no cross-project leakage. On edits invalidate only affected spans, exclude stale results, rebuild/resume boundedly; deletes/tombstones, project clone and backup restore preserve isolation. Default local storage of vectors even when generated by cloud. Embedding vectors are sensitive derived data; no automatic telemetry/export to cloud. Optional remote Cloudflare Vectorize sync is a later explicitly authorized feature, not required for Workers AI inference; separate remote index lifecycle, access control, retention/delete and privacy review. No use of actual account resources in GAIS development.

Use exact structured lookup + lexical ranked retrieval (e.g. BM25 or justified alternative) + semantic top-k per enabled compatible index. Fuse rankings using rank-based approach (e.g. reciprocal rank fusion), deduplicate by anchored chunk and diversify/context-expand; never mix vectors or uncalibrated scores. Prefer exact evidence when answering factual queries; optional semantic matches are relevance hints, not narrative facts. Filter by project/scope/revision/spoiler boundaries before ranking and after retrieval. Use operation-specific budgets and context inspector; retrieval does not equal exhaustive analysis. Full diagnostics/sync need explicit partitioned complete scope plus cross-partition fact reconciliation, exact coverage, failed/omitted chunks and no fabricated guarantee of detecting every contradiction. If all embeddings offline return deterministic results and indicate semantic unavailable; no automatic network or provider substitution. Local index and pre-existing vectors survive restarts; query vector generation still needs compatible runtime unless cached for exact query. Backup author-owned data always; derived indexes optional export and safe rebuild (cloud rebuild requires explicit action).

Require explicit per-project consent for sending passages or queries externally; clearly say what leaves device. No indexing on typing, launch or import via cloud by default. Explicit bounded build with progress, budget, cancellation and resumable checkpoint. Optional future local incremental embeddings may be enabled explicitly with local resource limits. Cloud keys never in renderer, browser storage, logs, backups, repository; no arbitrary private-network fetch from hosted server. Use secure existing credential boundaries. Provide synthetic bilingual retrieval fixtures, exact vs paraphrase search, same-dimension incompatible vectors, partial/missing provider, stale/deleted spans, changed chunk/version, budget exhaustion, spoiler filter, no unauthorized traffic and deterministic fallback tests. Verify actual availability separately per environment; honest disabled state over mock success.
