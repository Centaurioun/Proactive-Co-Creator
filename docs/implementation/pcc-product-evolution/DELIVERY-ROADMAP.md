## Common execution rules
- Read current assigned task, blueprint, relevant research and source. Establish actual environment revision or workspace inventory/hash if .git absent; record baseline. Preserve user work, unrelated files and previous decisions. No unapproved deploy, merge, live personal provider use, external account resource creation, secret handling outside secure existing paths.
- Use appropriate Superpowers methods when available (brainstorming for design, systematic debugging for actual failure, writing-plans for decomposition, regression tests and verification before completion); if not installed apply equivalent six cycles and disclose. Plan briefly, implement substantial blocks, validate actual behavior, refine; avoid repeated ceremonial reports. User wants actual product working; no large unrelated CI/toolchain rewrite. Preserve manifest/lock coherence, use existing dependencies unless justified, no fabricated lock or version downgrade. If baseline lock mismatch and manifest unchanged, restore exact known-good lock if verified compatible; otherwise regenerate only with actual tooling and validate, report blocker if impossible.
- Six cycles per package: inspect/scope -> reproduce/trace -> design alternatives/decompose -> critical risk/constraint review -> implement/verify/refine -> integrate and acceptance. Apply at meaningful milestones rather than endless cycles. Test crucial regressions as changes are made, full available checks and real preview journey near closure. No mock-only success claims, no skipping failing critical paths. Keep synthetic fixtures and bounded managed Gemini calls; no personal provider/desktop claims without actual evidence. Explicit user-triggered operations and no hidden fallback/retry/continuation; existing legitimate bounded provider retry only as allowed, single-attempt ChatGPT preserved.
- Preserve four authorities, CAS/revision/tombstones, explicit author application, migration/backup compatibility, exact source anchors and provenance, no silent data truncation. User data must survive interrupted work. No application of unvalidated AI outputs. No external embedding calls by default or personal API keys in workspace.
- For each internal milestone persist progress to the package's CHECKPOINT.md before moving on: task ID, status (NOT STARTED/IN PROGRESS/IMPLEMENTED/VERIFIED/BLOCKED/DEFERRED), files changed, actual tests/preview evidence, remaining risks and exact next step. Save completed files progressively. If Git available, commit safe coherent milestones on assigned work branch only; if absent use workspace file saves and inventory. Do not fabricate commit SHA or auto-push. Do not repeat already completed work after timeout; recheck current files and checkpoint for mismatch. No reset/revert unrelated changes.
- At package completion create REPORT.md and update checkpoint with per-task requirement-to-code/evidence mapping, tests commands/results and actual live/preview journeys, unverified areas, known remaining failures and exact changed files. Completion requires delivered code plus evidence; use PARTIAL/BLOCKED if appropriate; no blanket “without issues.” If one task blocked, proceed independent safe tasks, record blocker and revisit where possible. Stop at package boundary, not next package. Owner pushes and independent reviewer inspects actual diff.
