# 09 — Refined design V4: Working Manuscript, chapters/scenes and narrative synchronization

Date: 2026-11-24. Status: product direction AGREED / detailed defaults DELEGATED; implementation NOT STARTED. Builds on 03, 05, 06 and owner approval 08. Decisions are design-level, not executed tests. No Figma file or production code changes here.

## 1. Product scope and observed baseline
Source reviewed: main 0b34d01fb0feb0e73655291f572e370fd95e0fe4. shared/types.ts:306–368 GenerationArtifact includes storyText, revisionId, mode and generation metadata; CreativeProject contains snapshot/artifacts/revisions/undoHistory. OutputGallery.tsx:62–72 selects stored artifacts; projectController.ts:105–108 refreshes artifact currentness; generated artifacts are created with source revision and retained rather than editor documents. Existing accepted proposals, stale revision checks, undo/redo and durable save are valuable primitives. Scene category in graph is not a chapter/scene document editor. No complete manuscript editor or durable source registry today. Do not confuse prompt, scene node, generated artifact and working prose.

Product direction: keep all prior accepted import, evidence/audit, diagnostics/opportunities, visualizations, backups and exports. Add a writer-focused editor, not a Word clone. A user may still start with an idea and graph only, with no mandatory chapter setup. Support import → editable manuscript → continued writing and native project → generated draft → adopt → edit. No automatic replacement of active text by AI output. Keep existing Story/Image generation and gallery, no new video/provider/cloud/team feature. Original source preserved; user decides canonical intent and prose. Three distinct domains (source, working text, structured narrative) plus generated artifacts.

## 2. Alternatives and selected architecture
A. Artifact-as-editor: edit existing GenerationArtifact.storyText directly. Cheap initial UI, but destroys historical generation provenance, conflates source revision and later edits; reject.
B. Full word processor/real-time bidirectional AI rewrite: rich formatting but enormous scope, cost, accidental rewriting, sync feedback loops and data divergence; reject.
C. Structured writing workspace with versioned chapter/scene documents, lightweight editor, explicit bidirectional reconciliation: selected. Maintain immutable source/artifact history, stable IDs and unified transaction review. Ordinary text entry autosaves locally; structural changes and AI patches explicit, graph and prose changes never silently overwrite each other. A later richer editor is possible without changing this authority boundary.

## 3. Information architecture
Project hub: Start from Idea, Import Story, Export, Backup & Restore; Settings separate. Workspace logical modes Write / Plan / Review (names provisional, navigation not forced wizard); Writing view prioritizes text, collapsible manuscript outline left, contextual inspector right on wide screens; mobile full editor with drawer/outline and issue detail sheet. Planning includes Story Bible, graph and alternate visualizations, decisions; Review includes Diagnostics, Opportunities, Evidence & Audit, history; gallery remains discoverable. Contextual links rather than top-level tab for each feature. Hide distracting overlays in Focus mode, keep save/errors visible; keyboard and responsive acceptance later Figma. No fixed final UI.

Writing outline: manuscript → ordered chapters → ordered scenes → stable paragraphs/blocks. Allow unchaptered text, one untitled chapter/scene or unsectioned draft initially; no fabricated chapter headings from plain TXT. Add/rename/reorder/split/merge chapters/scenes, preview destructive operations; preserve IDs and text order, explicit discard/restore; drag-drop plus accessible keyboard reorder, stable selection, search. Display word counts, status (draft/revised/final as author labels, not locking unless explicit), synopsis and optional POV/location/time references; no required metadata for writing. Story order vs event chronology distinct, flashbacks allowed. Keep chapter headings actual versus inferred suggestions distinct. Scene may reference existing scene entity without creating duplicate authority. Multiple works in one project deferred; one primary working manuscript per project for first version. Native project empty until author starts writing/adopts artifact; no automatic AI to fill missing text.

Editor MVP: paragraph/heading, basic emphasis, lists/quote where useful, Unicode/IME, undo/redo, keyboard shortcuts, search, word count, focus mode, paste safe text/limited formatting, normal selection editing, autosave with honest dirty/saving/saved/error. Choose editor library only after existing toolchain, accessibility, serialization fidelity, performance, licensing and security tests; no dependency choice yet. Prefer simple structured text/block representation with tested Markdown/plain text round-trip, no raw model HTML. Original DOCX byte preservation is different from visual reproduction; DOCX export can generate supported formatting, not claim pixel-perfect fidelity. Later comments, advanced styling, track-changes, collaboration only if justified.

## 4. Authority and data contract
- Original SourceDocumentVersion: immutable original bytes when retained, extracted exact/normalized text with parser/version and stable anchors/digest. For imported files default retain original bytes within explicit safe byte/decompression/storage budget; disclose local retention and external provider transmission, allow extracted-only option before import and clearly label reduced backup fidelity. Pasted text has original text but no file bytes. Never discard original silently or embed repeatedly in each revision. No network fetch of embedded URLs. Source deletion is explicit and referentially safe; privacy deletion/export scope defined.
- WorkingManuscript: manuscriptId, projectId, ordered chapter IDs, chapter/scene/block records, revision/version and content digests. One authoritative editable version, immutable revision references or deltas; avoid whole novel copies in project snapshots and every keystroke. Stable scene/block IDs survive reorder, split/merge with lineage; immutable historical evidence stays anchored to old version. Exact representation and migration to be tested, not preordained schema4.
- Narrative Model: current accepted graph/Bible/relationships, author constraints and decisions; typed semantic facts/provenance. Text and model each have domain authority: source proves original wording, working text proves current wording, canonical model expresses intended accepted facts. Neither can automatically overwrite the other. Divergence may be intentional (unreliable narrator, draft not yet synchronized, different time periods), not automatic error.
- GeneratedArtifact: retain original generation output, prompt digest, model/source revision metadata. Adopt selected excerpt/new scene/append/replace with preview, creates working text revision and origin link, does not mutate original artifact. Image mode untouched.
- Evidence & Audit: shared registry and typed anchors to immutable original, working revision, generated artifact or canonical field/author decision. Record actor/approval/target/diff/basis, version and source kind. No fabricated citation for user-authored changes. Distinguish current versus historical evidence; block change → revalidate dependent claims, not rewrite immutable original citations.
- Revision/transaction boundary: compose text and graph changes as one logical operation with project ID, base project/manuscript versions, target digests, explicit patch preconditions, validated refs, audit event and durable commit. Storage authority must support atomic commit or verified recoverable protocol; if transaction fails no false success/partial accepted state. Undo/redo and restore must move relevant text/model references together, advance monotonic revision and retain audit (compensating event), not silently roll back unrelated newer work. Existing snapshot-only history cannot automatically provide this; characterize then extend. Conflict handling across tabs, late AI responses, deletion, import, restore and autosave through common save authority. No second independent state store.

## 5. Synchronization — detect automatically, reconcile explicitly
A. Text → model: author edits text and saves. Mark affected scene/block and known dependent claims as changed; cheap local validation and freshness automatically; no paid request every keystroke. User can Analyze Changes / Analyze Scene / Analyze Manuscript. AI returns proposed additions, corrections, conflicts, ambiguities with source spans, target IDs, base version. Show new vs existing, accept selected/source-supported batch, reject/defer; approved changes become canonical. Missing facts are not deletions unless clearly explicit and approved; changed paragraph may only affect evidence freshness. If source evidence still true elsewhere, don't delete claim. Character beliefs, quotes, flashbacks and temporally scoped attributes not unconditional facts.
B. Model → text: author changes confirmed age/name/relationship or accepts AI operation. Update graph/Bible projections and affected references, mark possible prose mismatches; show linked scenes/blocks, no blind search-and-replace. User requests Sync Manuscript / Suggest Text Updates. AI offers limited targeted patches and rationale, exact old/new excerpts with preconditions, impact and optional alternatives. Choose one/none, apply selected approved patches only. Preserve voice and unrelated prose. Renaming a character in graph doesn't replace every matching word or ambiguous alias. If name occurs in dialogue intentionally, don't silently alter. Read-only original unaffected.
C. Cross-domain conflicts: shared Diagnostics shows Model-only vs Manuscript-only changes, possible contradiction vs confirmed technical mismatch, pending sync count, last checked revision/coverage. “Synchronized” only for evaluated scope and matching versions; no global truth guarantee. Graph overlays link to same issue and actual scene. User can acknowledge intentional difference, defer or clarify; unresolved/stale remain visible. Do not block normal writing for every pending issue; block unsafe apply/stale or invalid data only.
D. Targeted context: select confirmed facts, relevant scene(s), adjacent narrative context, user constraints and style profile with token budget and coverage; separate speculative/pending suggestions from facts; never silently truncate long source. Manual explicit AI requests default; bounded recursive dependency lookup with visited set and max scope; no autonomous repair loops. Re-evaluate changed dependencies after accepted edit, record residual issues. Model results are suggestions until verified/accepted.
Example: Leyla age 28 → 32 in graph, manuscript still says 28. Create divergence finding linked to affected paragraph/field; propose changing the paragraph, reverting graph, or explaining separate time periods (only with author context). Author may keep both as intentional chronology. Approve specific patch → text revision + canonical intent + issue status/audit saved consistently, verify current scope. Undo preserves original and reopens issue where applicable. Never claim all chapters fixed if only one reviewed.

## 6. Writing AI assistance and reuse of existing mechanisms
Selection-level actions: Rewrite selection, Improve clarity, Shorten/Expand, Continue scene, Suggest dialogue/alternatives, Analyze consistency, Ask about source. Scope and optional prompt clear; show before/after with textual +/- and accessible diff, quote evidence when relevant, no changes outside scope. Generated output preview, accept selection/append/replace/new scene, reject or retain alternate draft; existing Decision Inbox/review/transaction concepts reused, not force prose into graph operations. AI-generated story remains gallery artifact until adopted; no auto insert. Reconstruct & Enhance remains distinct from Faithful import; no creative edit during faithful reconstruction. Existing user-created manual content supported offline/local; unavailable AI does not prevent writing/export/backup. Creative Opportunities proposes ideas without labeling subjective choice defect. Provide context disclosure and cost policy; no paid API CI. No default ongoing auto AI.

## 7. Import, append, export, recovery
Initial import creates new project and working manuscript copy from source (unchanged, user-reviewed mapping). Respect exact source order, headings, paragraphs and unsupported formatting warnings. AI segmentation proposals may be accepted to establish chapter/scene boundaries; do not fabricate headings/changes or silently lose text. Keep no-source/native projects possible. First release new-project import; existing-project append is accepted follow-on feature, not discarded: preview chapter insertion/merge/dedupe, source-version identities, base revision guard, conflict and explicit confirmation. Never overwrite existing text/graph automatically.
Content export: original file if retained vs extracted source text vs working manuscript selected chapter/scene/full vs generated artifact. TXT/MD first, DOCX export with documented supported styles, JSON evidence/issue/audit, optional ZIP selected files with manifest; complete backup separately. Deterministic filename/extension/revision convention V2. Restore includes source assets, manuscript version refs, graph, artifacts, evidence/issues/audit and editorial history as promised by format, checksum validation and missing asset explicit. Managed internal backup + permissioned external folder from V3, no arbitrary path or remote disk assumption. Before destructive operation create verified checkpoint when required; quota errors visible, protect sole recovery point. Source/draft sizes and retained revisions benchmarked, storage budget measured; no silent eviction of important data. Privacy deletion and backup deletion separate explicit choices. Old schema3 projects/JSON remain loadable and behavior preserved.

## 8. Six-cycle iterative refinement (V4)
| Cycle | Failure mode examined | Refined decision | Future verification |
|---|---|---|---|
| 1 — Product scope | Word clone or mutate immutable generated outputs | Writer-focused versioned working copy and preserve gallery/source | Import/native draft/adopt/reject; old output remains unchanged |
| 2 — Structure | Force chapters on plain text; reorder invalidates IDs and citations | Optional structure, stable IDs/lineage, separate narrative order vs chronology | Round-trip, unstructured text, split/merge/reorder, keyboard, no lost paragraphs |
| 3 — Authority | Automatic two-way sync rewrites author intent, false conflicts | Local freshness/impact automatic; explicit AI proposals, source/working/model authority separated | Manual edit, graph edit, unreliable narrator, temporal cases, no AI/no mutation before approval |
| 4 — Transaction | Text save succeeds but graph/audit fails; stale result overwrites new edits | Common transaction with dual revisions/digests, atomic/recoverable save, undo/restore both domains | Fault injection, cross-tab, late response, deletion, stale patch, compensating undo |
| 5 — Scale and recovery | Whole novel copied per keystroke and sent every request | Version refs/block storage, token-scoped context, backups complete and verified | Long manuscript and quota, chunk coverage, export parity, backup restore on supported browsers |
| 6 — Delivery and UX | Big-bang implementation on hotspot modules, nine tabs, premature library choices | Dependency-ordered slices, writing-first IA, staged Figma + engineering proof, preserve old behavior | Existing A–I, new journeys/accessibility, benchmark, schema migration/rollback, review each PR |

Review as hypothetical builder (self-review, no separate reviewer run): biggest implementation-dependent uncertainties are storage transaction mechanism and migration, editor serialization/IME and accessibility, actual source limits/AI provider capabilities, canonical-to-prose link completeness. These cannot responsibly be fixed as guessed numeric values now. Resolve via bounded engineering spikes/tests before production design commitments, not another owner preference questionnaire. Product defaults above selected under delegated authority; user can later revise them. No software tests executed in this document.
