Date: 2026-11-24. Status PROPOSED / DISCOVERY. Builds on V1/V2 and owner feedback 04. V2 conceptual agreements recorded separately in 06; new V3 proposals not yet owner-approved. No implemented feature, executed test, Figma design or model quality result claimed.

## 1. Source grounding and product direction
Reviewed main 0b34d01fb0feb0e73655291f572e370fd95e0fe4 and existing PR #7 archive. Current `App.tsx:620–623` derives consistencyIssues via useMemo/evaluateProjectConsistency(snapshot). `lib/consistencyChecker.ts` is lightweight deterministic rules (explicit exclusions, limited English regex trait contrast, primary setting comparison, unresolved core Bible fields). Header comment mentions contradictory relationships, but actual function body lacks a dedicated relationship-conflict rule; don't overstate current coverage. English lexical heuristic, substring matches and timeless traits can create false positives and miss Turkish/multilingual/temporal contradictions. Unconfirmed Bible fields are readiness findings, not contradictions. Current `ContextualInspector.tsx:1319+` shows Checks and stable-target navigation via resolveConsistencyIssueTarget; `BeliefGraph.tsx` already has category filtering, directed relation selection, table and graph views, pan/zoom and structural layout stability. `storageEngine.ts` schema3, IndexedDB/localStorage, pre-migration backup key, quota protection, tombstones/CAS and durable save; this is not general user backup catalog. `historyEngine.ts` currently caps undo stack at 40 and revisions at 25; history is not an independent recoverable backup. Existing AI analyze/clarify/batch/refine/generate routes are not a complete semantic diagnostics/opportunities system.

Goal: project-wide narrative intelligence for both original creation and imported stories. Separate diagnostics (possible problems) from opportunities (optional creative improvements), evidence/audit and graph projections. Share canonical source of truth and proposal/transaction boundaries; no duplicate truth stores, no hidden rewriting, no unsolicited paid AI calls. Current import's Faithful mode remains strictly non-creative. Exact layout later Figma.

## 2. Brainstormed alternatives
A. Separate AI agents repeatedly analyze every edit and maintain their own graphs/issues/backups: high latency/cost, loops, divergence and unsafe mutation; reject.
B. One manual analysis button that replaces existing Checks with unstructured AI prose: cheap UI, loses deterministic check strength, stable targets and issue lifecycle; reject.
C. Hybrid diagnostics + explicit opportunities + synchronized projections + explicit recovery: retain local rules, request semantic AI analysis with budget, structured finding registry and stable references, incremental impact revalidation, optional future auto AI with consent; recommend.
Navigation: retain project hub Import / Export / Backup & Restore and global Settings. Workspace diagnostic center (Checks) with Problems/Readiness/Review filters and separate Opportunities view, Evidence & Audit and Revision History. Visualization view switcher (existing Belief Graph, Character Relationships, Mind Map) rather than extra data silos or mandatory top-level tabs. User can navigate from a graph warning to issue/source and back. Actual placement and mobile accessibility for Figma.

## 3. Continuous diagnostics
Two layers:
- Local checks: inexpensive deterministic rules after committed snapshot changes (debounce/affected-rule evaluation when needed, not every keystroke network call). Keep stable IDs, separate confirmed invariant violations, possible warnings and missing decisions; improve lexical checks only with tests. Examples: dangling relation references, excluded entities in confirmed relations, conflicting single-value properties with same temporal scope. Relationship symmetry/inverse/type semantics only for explicitly modeled rules; not every friendship/hostility combination is contradiction.
- Deep AI analysis: explicit Analyze Consistency action, current revision + source/work manuscript/confirmed graph/Bible with selected scope. Options Quick (local), Focused AI (selected character/relation/scene/issue), Full Review (bounded project-wide review with coverage summary). Return structured candidates, evidence and uncertainty, never mutation. Import findings and ongoing findings share registry. Source absent for native-created stories? cite project revision, user-authored fields, decisions, generated artifact excerpts or user notes as applicable; no fake manuscript chapter. Separate authored canonical vs unapproved AI/generated prose and character belief. Show last analyzed revision/time/scope/provider, source coverage, freshness, missing/unreviewed areas and status. “No issues detected in checked scope” not guarantee story consistent.
- Automatic local graph projections and affected rule rechecks after any manual/AI accepted edit, undo/redo, restore or import. Deep AI by explicit user action default; future opt-in event/debounce/on-save with budgets if justified. No polling or AI recursive self-fixing default. Existing pending/user authority rules retained.
- Impact analysis: stable target/claim dependency index (entity IDs, relation IDs, Story Bible fields, source blocks/working text revisions, issue/proposal IDs). Track changed items and bounded neighborhood, visited set for cyclic graph, dedupe, graph relation direction and dependency type. Not every transitive graph neighbor logically affected; mark possible impact, do not infer truth by propagation. Invalidate stale findings/proposals whose evidence changed; unrelated edits need not make everything stale. Local re-evaluate; mark semantic findings needs recheck, no automatic resolved on disappearance. On explicit Analyze, choose changed-since-last / selected / whole-project; display coverage. Revalidate approved correction before declaring resolved; if source prose unchanged and contradictory, distinguish representation corrected from manuscript unresolved.
- Data contract: extend V2 Issue with detector (rule/model/manual/import), ruleCode or analysisRunId, issue fingerprint/stable ID based on type+canonical affected claims+scope (not wording), severity, certainty, status and freshness independent, evidence refs, projectId/base revision and dependency digests, target locators, timestamps first/last observed, resolution events. Deduplicate reanalysis, preserve owner dispositions, re-open only if condition meaningfully reappears or evidence changed; no resurrecting dismissed intentional ambiguity without new reason. Retain audit of proposals, dispositions and applied changes; compact retention policy. Draft analysis jobs scoped by run/project/revision; cancel/late/superseded/invalid output cannot overwrite project or close issues. No uncontrolled repair loops, bound iterations and show remaining work.
- UI: overview counts Open/Deferred/Needs clarification and freshness, list filters severity/type/character/source/changed since, contextual actions View evidence / Go to entity / Suggest fixes / Review later / Clarify / Intentional / Reopen. Severity color plus icon/text; accessible table/list. User can mark intentional (record reason) and recheck affected issue; do not treat lack of detail as flaw.

## 4. Suggest Fixes: alternative proposal sets
Default request up to three meaningfully different candidate fixes (one/two or no grounded options permitted; don't force hallucinations to fill three). Include “None of these”, “Add guidance”, “Generate different options” and cancel. Distinguish proposed fix options from resolved status; AI output only structured, schema/target/evidence validated, base revision and preconditions, no auto apply.
Each option: stable proposal/group ID, intended issue, concise rationale, assumptions, target kind (graph/Bible/working prose if supported), source or project refs, exact before/after diff, impacted items and potential new contradictions, how to verify. Example same-revision age mismatch: correct attribute to match source, correct representation if author confirms alternate value, or clarify differing times; intentional/no edit also available. Don't choose automatically; user can decline all, provide clarification or request alternatives. Rerun may cost tokens, reuse previous option fingerprints and explicit feedback to seek diversity, bounded retries/calls; retain meaningful rejected/applied audit, don't fill revision history with untouched option generations. No guarantee novel alternatives.
Apply: user selects one, review actual diff and scope, explicit approve, validate current base+dependencies; if stale require re-preview, don't blindly replay. Use existing transaction/undo/revision/save authority; one logical atomic commit, not partial writes. Recheck impacted rules and semantic analysis as appropriate; link correction event; show unresolved residuals; undo compensating event and reopen if issue returns. Source original immutable; working prose editor not yet agreed. Correction of extraction error in faithful mode is allowed as representation correction; creative changes never offered within Faithful Import. Post-import user can opt into creative editing separately. UI in-app safe text rendering with red deletions/green additions, strike-through/addition markers, accessible before/after text, no raw untrusted HTML injection. Export same event records JSON/MD. Never label manuscript fixed when only canonical field changed.

## 5. Creative Opportunities
Separate discovery operation from Diagnostics. Defect = conflict with known constraints; opportunity = subjective optional path, not mandatory, not a warning. User presses Explore Improvements with optional intent (genre, target scene, tone, constraints, desired depth). Analyze project or selected scope, offer limited ranked-by-relevance suggestions with rationale, evidence/target, potential benefits, tradeoffs, impact and assumptions; no invented facts inserted in canonical context. Categories: character depth/arc/motivation, relationship dynamics, stakes/conflict, pacing, theme, worldbuilding, setups/payoffs, alternate story branches, voice/continuity/style. Respect author exclusions, existing confirmed decisions, intended ambiguity, cultural/language context; don't impose formula, genre stereotypes or change names unasked. Avoid suggesting something already implemented; no fabricated popularity metrics or quality score. Could have “Explore alternatives” for user-defined what-if branches, not auto-rewrite.
User can save idea, reject, defer, ask for alternatives or convert to staged proposal (reuse Decision Inbox/review diff/batch machinery where appropriate). Only accepted transaction changes canonical/working copy; pending idea not a confirmed story fact. Re-evaluate impact after applying; avoid feedback loop where every suggestion generates AI requests. Track suggestion basis/revision and stale status. Optional opportunity generation distinct from faithful import and not silently part of consistency check. MVP focused manual recommendations, not autonomous writing agent.

## 6. Narrative visualization
Existing Belief Graph remains authoritative data projection, not data authority. Three views recommended:
- Belief Graph: all characters/locations/objects/events/groups/scenes and typed directed links, existing table accessible fallback.
- Character Relationship Map: character-focused network, relation filters (family, social, professional, conflict, alliance, romantic etc only supported labels), direct/indirect path exploration, optional selected character ego-network; relation direction/symmetry clearly represented, no fictitious kinship. Family Tree is optional specialized layout/filter only for verified kinship, not whole graph; cycles/adoption/stepfamily/multiple partners must not be forced into a simple tree. No separate canonical family database.
- Narrative Mind Map: topic/plot/character/world/theme/scene overview grouped by purpose, visual hierarchy is navigation not assertion of causal/kinship links. Cross-links to canonical IDs; manual grouping/layout preference separate from facts. If a theme inferred, show pending/provenance. Optional later timeline projection.
All views derive from current project+issue registry and shared stable IDs; automatic updates after commits without AI calls, preserve layout positions/zoom/selection where practical, filter by scope/time/confirmed/pending/excluded and issue status. Warning on affected node/edge (not entire graph), icon+color+count and list/details panel, selected issue highlight and connected source/audit, click/focus target. Distinguish error, possible warning, deferred, stale, resolved; legend, keyboard/screen reader table, mobile zoom/filter and no color-only information. Shared issue ID across views so no duplicates. If entity removed, historical target shows unavailable, no guessed name remap. Large graphs: filtered ego views/virtualized list, measured layout performance, avoid rerender/re-layout every nonstructural edit. Graph relationship edges do not by themselves imply logical dependency; bounded impact path explicit. Editing in any view uses shared canonical transaction; layout-only edits never mutate story. Exact layout/components in Figma.

## 7. Backup, restore and export
Distinguish 4 concepts: autosave current working state; revision history/undo (bounded editorial history); managed recovery snapshots (“Create Backup”, “Restore Backup”) independent logical recovery records; portable export (“Export Backup”/“Download Backup”) user chooses location/sharing. Content export separate.
Current app runs as browser web app with Express server possibly remote (AI Studio), not desktop local filesystem authority. Browser cannot silently write arbitrary home/Documents paths; showDirectoryPicker requires user activation/permission/secure context and isn't universally supported; OPFS private per origin, IndexedDB/OPFS share storage risks, browser data clear/profile loss may remove all. Server filesystem may be remote and must not be treated as user device. Sources: https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker ; https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system ; https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria .

Alternatives:
A. Browser-managed backup vault (IndexedDB dedicated records/possibly OPFS blobs after benchmark): universally feasible with capability checks, manual Create Backup, list/restore/verify, no download needed. Protects against bad edits/accidental project changes, not browser/site-data loss. Request persistence where supported; clearly label location and limitations, don't claim external backup. Recommended baseline.
B. User-selected external folder via File System Access API in supported browser contexts: one-time choose Backup Location (suggest Documents/Proactive-Co-Creator/Backups, visible folder preferred over hidden home for recovery). Save verified snapshots there on explicit Backup; optional auto while app running and permission valid, capability check and reauthorization, clear status/fallback. Cannot assume persistent permission, browser/AI Studio iframe support or background execution. Never write unrelated files, never ask for broad home access. Unsupported browsers use portable download/folder manual restore. Recommended optional tier.
C. Local desktop app or explicitly configured local server storage (platform-specific app data / user chosen directory) only if future deployment warrants; not current web feature. Remote hosted service/cloud backup requires separate architecture/auth/privacy approval. No arbitrary path endpoint or remote manuscript storage added.
Backup center: project-specific and all-project backup selectable (aggregate later if scope complex); optional name/label, created time, source project IDs/revision, schema/version, completeness, size, checksum manifest, destination/internal vs external, verified/error status. Include canonical snapshot, history/undo within defined retention, artifacts, immutable sources/original bytes per policy, evidence/issues/audit/metadata; distinguish complete vs partial. App settings separate optional non-secret backup, never API keys. Manual backup does not require export/download. Before destructive restore/schema migration/large batch optional/mandatory safety checkpoint as appropriate; if checkpoint fails do not proceed silently. Autosave distinct, not a new full backup on every keystroke. Consider user opt-in periodic/after major revision backup while app open; deduplicate identical content, configurable retention/size, pinned backups, explicit confirmed deletion and quota failure handling, no silently evict sole verified recovery copy. Keep last known good until new archive committed+verified. Backup cannot promise device disaster recovery unless independently stored (external drive/other location). No full disk path shown unnecessarily. Verify integrity/readback and restoration test, not just write completion. Restore preview schema/version/time/project/count/assets, collision default copy with fresh project ID, explicit replace and safety checkpoint; validate no arbitrary ZIP traversal/bombs/executable, preserve tombstone/CAS/cross-project isolation, old JSON supported, missing sources clearly flagged. Do not reset history invisibly. Project deletion policy distinguish backup retention with clear warning; privacy delete-all path explicit and permission-aware. No automatic purge.
Export center: selectable content, formats and optional “Bundle selected files into ZIP”, no requirement to zip. Generate deterministic JSON/MD from registry, original/working/generated distinction, filename V2 convention. ZIP selected content with manifest, safe relative paths, stable IDs, no secrets; not a full backup unless complete restorable contract explicitly met. Download existing managed backup without reanalyzing/recreating; verify it matches selected revision. In-app diffs and evidence view primary, export optional.
Backup testing: save/readback integrity, simulated disk/quota/permission revoked, partial write/interrupt/crash, corrupt archive, duplicate ID, restored refs/undo/audit, retention and pinned behavior, internal-only vs external loss warnings, Firefox/Safari fallback and Chromium actual folder capability, local vs remote deployment, no credential leakage. No backup filesystem write performed in discovery.

## 8. Six-cycle iterative refinement V3
| Cycle | Initial assumption / stress case | Refinement | Future evidence gate |
|---|---|---|---|
| 1 — diagnostics | New inconsistencies tab and always AI; native/user-edited stories overlooked by import-only analysis. | Existing local Checks + explicit bounded semantic analysis for every project; separate readiness/possible/confirmed and coverage. | Manual/AI edit, import, multilingual and temporal fixture, no network before consent. |
| 2 — corrections | Force three AI fixes, regenerate until accepted, auto-fix recursively. | Up to three diverse validated proposals, none/clarify/retry budget; preview/approval/stale guard/atomic apply, bounded impact and recheck. | No auto apply, rejection preserves project, stale response/cycles, undo/reopen, actual diff. |
| 3 — creative value | Mix suggestions with defects and imply one correct artistic outcome. | Distinct Opportunities, author goals and optional alternatives, staged review and no confirmed changes without approval. | Intentional ambiguity/genre constraint, no insertion on discovery, stale and dismissed idea behavior. |
| 4 — visualization | Separate family tree and mind map data stores; every edit triggers full redraw/AI. | Shared graph projections, family-only special view, explicit direction/temporal scope, issue overlay from shared registry, incremental layout. | Stable cross-view IDs and counts, graph cycles, no orphan targets, keyboard and large graph benchmarks. |
| 5 — recovery | Autosave or hidden folder assumed reliable backup; server may be remote. | Internal recovery vault + optional permissioned external folder, portable export separate; verified archives, retention, fallback and clear loss boundary. | Actual restore, denied permission, quota, crash, malformed archive, browser portability and warning text. |
| 6 — integration | Implement all at once on hotspot modules or overwrite prior decisions. | Staged architecture with common issue/evidence/audit contracts, snapshot/projection separation and backup safety before mutation, append-only discovery/decision log. | Full old CI and new suites, schema/migration roundtrip, independent PR review, Figma acceptance, no live paid calls in CI. |

These are design reasoning cycles, not executed software/model tests. No numeric accuracy, cost or speed claims. For future evaluation use hand-labelled multilingual examples including contradictions vs intentional shifts, graph edge direction and fidelity, suggestion usefulness evaluated by author, no accepted changes without intent, backup recovery drills.
